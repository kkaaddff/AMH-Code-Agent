# 述职答辩 Q&A 准备

## Q1: 你为什么做这个项目？ (Why)
*   **宏观视角**: 响应公司/行业对“降本增效”的极致追求。传统的“设计->开发”手工作坊模式已经成为瓶颈，AI Agent 技术爆发为解决这一经典的 Code-to-Design 难题提供了新的、可落地的解法。
*   **微观视角**: 我观察到团队同学在还原 MasterGo 设计稿时，花费大量时间在 CSS 调整和 DOM 结构搭建上，且经常出现“差 1px”的视觉还原 Bug。我想通过自动化工具释放这部分人力，让大家专注于更复杂的业务逻辑（如状态管理、交互优化），提升工程师的成就感。

## Q3: 你的优势是什么？比别人强在哪里？ (Advantage)
*   **全栈视野与工程落地**: 我不仅仅关注单一端，而是整合了 Midway 后端、React 19 前端和 LLM Agent 技术。能将复杂的 AI 概念（Prompt Engineering, Function Calling）落地为稳定可靠的工程链路（Redis 缓存、Bull 队列、CLI 回放），这是很多纯算法或纯前端同学不具备的。
*   **产品思维驱动技术**: 我不满足于“能用”，而是关注“好用”。例如开发了 **3D Inspect** 视图，解决了 2D 视角下复杂图层难以选中的痛点；实现了 SSE 流式反馈，让 AI 生成过程不再是黑盒，提升了用户的信任感。
*   **深入的领域认知**: 对 Design DSL 有深入研究，不是简单调 API，而是编写了 `DSLCleaner` 等算法来处理“层级塌陷”等边缘情况，确保了生成代码的高可用性。

## Q4: 项目中最大的技术挑战是什么？ (Challenge)
*   **挑战**: MasterGo/Figma 等设计工具导出的原始数据（PATH/Node）往往杂乱无章，存在大量冗余图层和复杂的相对坐标，直接喂给 LLM 会导致 Token 爆炸且理解偏差。
*   **解决**: 我设计了多阶段 **DSL 归一化流水线**：
    1.  **解析**: 短链换取原始 JSON。
    2.  **几何清洗**: 自研几何算法处理坐标（如 `DSLCleaner`），计算绝对坐标，剔除无效节点，解决视觉层级与 DOM 层级不一致的问题。
    3.  **标准化转换**: 将非结构化的 PATH 转为标准化的 LAYER/PNG，利用 Redis/Mongo 双写缓存优化性能。
    4.  **语义化**: 最终生成干净、带有语义的 DSL 投喂给 Agent，大幅提升了 AI 代码生成的准确率。
