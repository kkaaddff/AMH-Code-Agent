## 简介
本文档详细阐述了设计稿管理功能的完整流程，包括设计稿的接入、解析、存储和版本管理。系统通过MasterGo API获取设计稿并转换为内部DSL格式，该DSL数据存储在MongoDB的design_documents集合中。文档描述了设计稿的状态机（active/archived/deleted）和版本控制机制，为初学者提供操作指南，并为高级开发者深入解析核心实现细节。

## 设计稿接入与解析
设计稿的接入与解析是整个流程的起点。系统通过MasterGo API获取设计稿数据，并将其转换为内部使用的DSL（Domain Specific Language）格式。

### MasterGo API集成
系统通过`MasterGoService`类与MasterGo API进行交互。该服务提供了从MasterGo URL提取fileId和layerId的功能，并通过这些ID获取DSL数据。

```mermaid
sequenceDiagram
participant 前端 as 前端应用
participant Controller as FrontendWorkflowController
participant Service as FrontendWorkflowService
participant ProjectService as ProjectService
participant MasterGoService as MasterGoService
前端->>Controller : POST /code-agent/frontend-workflow
Controller->>Service : runWorkflow(designDocId)
Service->>ProjectService : getDocumentContent(documentId)
ProjectService->>MasterGoService : getDslFromUrl(mastergoUrl)
MasterGoService->>MasterGo API : GET /mcp/dsl?fileId=&layerId=
MasterGo API-->>MasterGoService : 返回DSL数据
MasterGoService-->>ProjectService : 返回DSL响应
ProjectService-->>Service : 返回文档内容
Service->>DesignDSLService : processDesignDSL(dsl)
DesignDSLService-->>Service : 返回处理后的DSL
Service-->>Controller : 返回工作流结果
Controller->>前端 : SSE事件流
```

## 设计稿状态机与版本管理
系统通过状态机和版本控制机制来管理设计稿的生命周期。

### 设计稿状态机
设计稿有三种状态：active（活跃）、archived（归档）和deleted（删除）。状态转换如下：

```mermaid
stateDiagram-v2
[*] --> active
active --> archived : 归档
active --> deleted : 删除
archived --> active : 恢复
archived --> deleted : 删除
deleted --> [*] : 永久删除
```

## 设计稿上传与预览操作指南

1. 在前端界面点击"上传设计稿"按钮
2. 输入设计稿名称和描述
3. 粘贴MasterGo设计稿链接

5. 系统将自动从MasterGo获取DSL数据并存储

1. 在设计稿列表中选择目标设计稿

4. 前端渲染引擎将DSL转换为可视化界面
5. 用户可以在预览界面查看设计稿内容

### 核心处理逻辑
`getDesignDsl`方法的核心逻辑包括：

1. **获取文档内容**：通过`projectService.getDocumentContent`获取设计稿内容
2. **处理DSL数据**：通过`designDSLService.processDesignDSL`处理DSL数据
3. **过滤可见节点**：移除隐藏节点和outline节点
4. **压缩DSL数据**：通过`minifyDSL`函数压缩DSL数据

```typescript
// 伪代码表示核心逻辑
async getDesignDsl(designDocId) {
  // 1. 获取文档内容
  const documentContent = await projectService.getDocumentContent({ documentId: designDocId });
  const { dsl, annotationData, pageId } = documentContent;
  
  // 2. 处理DSL数据
  const processedDSL = await designDSLService.processDesignDSL(dsl);
  
  // 3. 过滤可见节点
  const filteredDSL = {
    ...processedDSL,
    dsl: minifyDSL({
      ...processedDSL.dsl,
      nodes: filterVisibleNodes(processedDSL.dsl.nodes)
    })
  };
  
  return filteredDSL;
}
```

## 缓存策略与性能优化
系统采用了多层次的缓存策略来优化性能。

### 缓存层级
系统实现了Redis和MongoDB的双重缓存机制：

```mermaid
flowchart TD
A[请求] --> B{Redis缓存命中?}
B --> |是| C[返回Redis缓存]
B --> |否| D{MongoDB持久化存储命中?}
D --> |是| E[返回MongoDB数据]
D --> |否| F[调用MasterGo API]
F --> G[转换SVG路径为PNG]
G --> H[上传OSS]
H --> I[持久化到MongoDB]
I --> J[写入Redis缓存]
J --> K[返回结果]
```

### 性能优化措施
1. **数值精度处理**：通过`normalizeNumericValues`函数将数值保留两位小数，减少数据体积
2. **DSL压缩**：通过`minifyDSL`函数压缩DSL数据，减少传输量
3. **路径转换缓存**：将SVG路径转换为PNG的结果缓存12小时
4. **SSE流式传输**：使用SSE实时推送处理进度，提升用户体验

```mermaid
flowchart LR
A[原始DSL] --> B[数值精度处理]
B --> C[过滤可见节点]
C --> D[DSL压缩]
D --> E[缓存结果]
E --> F[返回客户端]
```
